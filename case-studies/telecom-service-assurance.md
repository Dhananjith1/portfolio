# Telecom Service Assurance — ITSM & SLA Governance Dashboard

<small>Classification: Project-management simulation · Role: IT Project Coordinator / Scrum Master · Planning window: 2 weeks</small>

## Overview

This simulation explores how an IT service team could organise incident visibility and SLA governance across four service categories: Mobile Data, Broadband, Voice, and Payment Gateways. The scenario uses 30 simulated incident records to practise incident classification, reporting, delivery planning, and data reconciliation.

It is not an official project for Dialog, SLT-Mobitel, or another telecom operator. No operator systems or real customer incident data were used.

## Objective

Create a clear planning and reporting approach that helps a service team understand which incidents are within SLA, breached, or still pending, and identify the information needed for consistent reporting.

## Project-management work

- Defined a two-week delivery scope and a small set of reporting outcomes.
- Organised a 30-record synthetic incident dataset across the four service categories.
- Modelled incident status and SLA state (Met / Breached / Pending) for dashboard reporting.
- Planned a coordinated work sequence using Jira.
- Identified data-quality and reconciliation checks before dashboard figures are presented.

## Tools and artefacts

**Tools used or modelled:** Jira, Excel, Power BI Desktop, and Notion.

**Planning artefacts described in this exercise:**
- Project Charter and scope boundaries.
- RAID Log covering delivery, data-quality, and dependency risks.
- Decisions Log for scope and reporting choices.
- Data Reconciliation Report to compare source records with dashboard totals.
- Power BI dashboard concept for incident and SLA visibility.

The underlying editable Jira, Excel, Power BI, and Notion workspace files are not bundled in this documentation folder.

## Acceptance criteria for the simulation

- All 30 synthetic incidents are represented in the reporting dataset.
- Each incident is assigned to one of the stated service categories.
- SLA status totals reconcile to the incident register.
- The dashboard distinguishes Met, Breached, and Pending states.
- Any missing or inconsistent data is visible rather than silently treated as valid.

## Limitations

All records and outcomes are simulated. The dashboard is a portfolio exercise, not a live ITSM integration. No real telecom SLA performance, customer impact, or operational improvement is claimed.
